## 补记 2026-10-16：OpenAI 预设的请求参数（max_tokens / temperature）

起因：OpenAI 预设（gpt-6-luna，`openai_reasoning`）的测试连接发 `max_tokens: 200`、`temperature: 0.2`，真翻译也发 `temperature: 0.2`，怀疑会被 400 拒绝。只读查了官方文档（未登录、未提交任何东西）：

| 问题 | 官方文档原话（摘要） | 来源网址（2026-10-16 访问） |
|---|---|---|
| `max_tokens` | 已弃用，由 `max_completion_tokens` 取代，且「not compatible with o-series models」（链接指向推理模型指南）；`max_completion_tokens` 的上限包含推理 token | https://developers.openai.com/api/reference/ruby/resources/chat/subresources/completions/methods/create |
| `temperature` | 参考页本身只写取值 0–2，不提推理模型；迁移指南写「reasoning effort 不是 `none` 时，去掉 `temperature`、`top_p`、`top_logprobs`」（Chat Completions 还要去掉 `logprobs`） | https://developers.openai.com/api/docs/guides/latest-model |
| `reasoning_effort: none` 谁支持 | GPT-6 Sol、GPT-6 Luna 支持；GPT-6 Astra、GPT-6.1 Sol 不支持（发 `none` 返回 400） | https://developers.openai.com/api/docs/guides/latest-model ；https://developers.openai.com/api/docs/guides/reasoning |
| gpt-6-luna 本身 | 推理模型；`reasoning_effort` 支持 none / low / medium（默认）/ high / xhigh / max；支持 v1/chat/completions；页面没列出不支持的参数 | https://developers.openai.com/api/docs/models/gpt-6-luna |

结论与决定：

- `max_tokens`：文档明说与推理模型不兼容 → OpenAI 方式改发 `max_completion_tokens`。它把推理 token 也算进上限，取消勾选「关闭思考」（默认 medium）时 200 可能全被推理用掉、正文为空，所以测试连接给 2000（勾不勾都一样）；其他方式仍是 `max_tokens: 200`。
- `temperature`：按文档，gpt-6-luna 在 `reasoning_effort: none` 时**是收**的；但只要不是 none 就必须去掉。这个预设给陌生人用，会出现「不是 none」的情况：用户取消勾选「关闭思考」（默认 medium），或把模型换成 Astra / GPT-6.1 Sol（不支持 none，只能取消勾选）。所以 OpenAI 方式**一律不发 temperature**（用服务端默认值），不看「关闭思考」勾没勾。代价只是译文随机性略高于 0.2，比 400 报错好得多。
- 真翻译（流式）原来就不发长度上限，现在 OpenAI 方式也只是去掉 temperature。
- 规则按「关闭思考方式」= `openai_reasoning` 区分（不看地址、不看是否关闭思考），写在 `shotrans/translate/vllm.py` 的 `sampling_params()` 一处，测试连接与真翻译共用。自建 vLLM、DeepSeek、硅基流动、百炼的请求体与改动前一字不差（`tests/test_sampling_params.py` 逐种方式钉死键集合）。
